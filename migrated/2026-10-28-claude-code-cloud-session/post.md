Claude Code 는 말로 시키면 코드를 읽고, 고치고, 명령을 실행해 주는 AI 도구다. 원래는 내 컴퓨터에 설치해서 터미널(검은 화면)에서 쓰는데, **웹 브라우저나 휴대폰 앱에서 바로 쓰는 방법**도 있다. 이걸 **클라우드 세션**이라고 부른다.

이 글은 개발을 전공하지 않은 사람도 읽을 수 있게 썼다. 클라우드 세션으로 집 서버를 하루 종일 관리해 보면서 **실제로 막혔던 곳**만 골랐다.

## 한눈에 보는 차이

| | 내 PC 에서 쓰기 | 클라우드 세션 |
|---|---|---|
| 어디서 돌아가나 | 내 컴퓨터 | 인터넷 너머의 임시 컴퓨터 |
| 설치 | 필요 | 없음. 웹·앱에서 바로 |
| 작업 파일 | 내 컴퓨터에 남는다 | **세션이 끝나면 사라진다** |
| 인터넷 접속 | 내 컴퓨터처럼 자유롭다 | **허용한 곳만** 갈 수 있다 |
| 비밀번호·키 | 내 컴퓨터에 둔다 | 환경 설정에 넣는다 |
| 휴대폰에서 | 어렵다 | 된다 |

> 📌 "세션" 은 Claude 와 나누는 작업 한 판이라고 생각하면 된다. 새 세션을 열 때마다 깨끗한 임시 컴퓨터가 하나 새로 생기고, 거기서 작업이 이루어진다.

## 시작하는 법

1. 웹에서 Claude Code 화면을 연다.
2. 작업할 **GitHub 저장소**를 고른다. 저장소는 코드와 문서를 모아 두는 온라인 폴더다.
3. 할 일을 평소 말투로 적는다. 예: "이 블로그 글에 오타 있는지 봐 줘"

그러면 클라우드의 임시 컴퓨터가 그 저장소를 내려받아 작업을 시작한다. 여기까지는 어렵지 않다. 막히는 건 그다음이다.

## 1. 작업 공간은 사라진다 — 꼭 push 한다

클라우드 세션의 임시 컴퓨터는 **세션이 끝나거나 한동안 쓰지 않으면 회수된다.** 그 안에서 만든 파일은 같이 없어진다.

그래서 결과물은 **GitHub 에 올려(push) 둬야** 남는다. 실제로 세션을 끝내려 하자 이런 경고가 떴다.

```
There are untracked files in the repository. Please commit and push these changes to the remote branch.
```

"저장소에 아직 올리지 않은 파일이 있으니 올려라" 라는 뜻이다. 이 경고가 나오면 Claude 에게 "커밋하고 push 해 줘" 라고 말하면 된다.

> 💡 **커밋**은 "지금 상태를 기록해 둔다", **push** 는 "그 기록을 GitHub 에 올린다" 는 뜻이다. 둘 다 해야 다음 세션에서도 이어서 쓸 수 있다.

## 2. 비밀번호·키는 환경 설정에 넣는다 — 바꾸면 새 세션

서버 접속 키 같은 비밀값은 **채팅창에 붙여 넣지 않는다.** 대화 기록에 남기 때문이다. 대신 화면 위쪽의 **환경 이름(환경 메뉴) → Edit** 에서 **환경 변수**로 넣는다.

```
MY_SERVER_TOKEN=여기에 키
```

Claude 는 작업할 때 이 이름으로 값을 꺼내 쓴다. 값은 대화에 나오지 않는다.

여기서 많이 막힌다. **환경 변수는 세션이 시작될 때 한 번만 읽힌다.** 실제로 설정 값을 바꾼 뒤 이미 열려 있던 세션에서 다시 시도했는데, 계속 예전 값으로 동작했다. 세션 안을 확인해 보니 여전히 바꾸기 전 값이 들어 있었다.

**값을 바꿨으면 새 세션을 연다.** 이것만 기억하면 된다.

## 3. 인터넷은 허용한 곳만 — 막히면 주소를 추가한다

클라우드 세션은 보안 때문에 **아무 사이트에나 접속할 수 없다.** 환경을 만들 때 고른 네트워크 정책에 따라, 허용된 주소로만 나간다.

Claude 가 작업 중에 블로그 주소로 접속하려다 이렇게 막혔다.

```
autops.run:443 — connect_rejected (the egress proxy refused the connection or could not reach the host; a refusal most often means that the host is not allowed for this session)
```

"이 세션에는 그 주소로 나가는 게 허용돼 있지 않다" 는 뜻이다. 고치는 법은 간단하다.

1. 환경 메뉴 → **Edit** → **Network access**
2. **Allowed domains** 에 필요한 주소(예: `example.com`)를 추가한다
3. **Allow package managers** 체크는 그대로 둔다. 프로그램을 내려받는 데 필요하다
4. **새 세션**을 연다

> 📌 어떤 주소를 열어야 할지 모르겠으면 Claude 에게 오류 문장을 그대로 보여 주고 "어떤 주소를 허용해야 해?" 라고 물으면 된다. 막힌 주소 이름이 오류에 들어 있다.

## 4. 위험한 일은 멈추고 묻는다 — 권한 모드

Claude 가 실행하는 명령 중에는 되돌리기 어려운 것도 있다. 서버를 끄거나 파일을 지우는 일이다. 그래서 입력창 옆에 **권한 모드**를 고르는 칸이 있다.

| 모드 | 하는 일 |
|---|---|
| Accept edits | 파일 수정은 알아서 하고, 그 밖의 명령은 실행 전에 **승인을 묻는다** |
| Plan | 먼저 계획만 세워서 보여 주고, 승인하면 실행한다 |
| Auto | 대부분 알아서 실행하고, **위험해 보이는 일은 스스로 멈춘다** |

Auto 모드에서 서버(가상 머신) 하나를 꺼 달라고 했더니 이렇게 멈췄다.

```
Permission for this action was denied by the Claude Code auto mode classifier.
```

"자동 판단에서 위험한 작업으로 보고 막았다" 는 뜻이다. 고장이 아니라 안전장치다. 이럴 때는 두 가지 방법이 있다.

- 그 작업만 **내가 직접** 한다 (이때는 서버 관리 화면에서 버튼을 눌렀다)
- 모드를 **Accept edits** 로 바꾸고, Claude 가 물어볼 때 **내용을 확인하고 승인**한다

> ⚠️ 승인 창이 뜨면 무엇을 실행하는지 읽고 누른다. 특히 지우기, 끄기, 비밀번호 바꾸기 같은 작업은 한 번 더 확인한다.

## 5. 결과물은 GitHub 로 받는다

클라우드 세션은 내 컴퓨터에 파일을 직접 저장하지 못한다. 그래서 결과물은 보통 이렇게 받는다.

1. Claude 가 작업 내용을 **새 브랜치**(작업용 갈래)에 올린다
2. "PR 만들어 줘" 라고 하면 **풀 리퀘스트**(이 변경을 반영해 달라는 요청서)를 만든다
3. 내용을 보고 괜찮으면 **반영(merge)** 한다

이 블로그도 이렇게 운영한다. 클라우드 세션에서 글을 쓰고, PR 을 반영하면 자동으로 블로그에 올라간다.

## 처음 쓸 때 체크리스트

- [ ] 작업할 GitHub 저장소가 있다
- [ ] 비밀값은 채팅이 아니라 **환경 변수**에 넣었다
- [ ] 필요한 사이트 주소를 **Allowed domains** 에 넣었다
- [ ] 설정을 바꿨으면 **새 세션**을 열었다
- [ ] 끝내기 전에 **커밋하고 push** 했다

## 정리

- 클라우드 세션은 **설치 없이, 휴대폰에서도** 쓸 수 있는 Claude Code 다.
- 대신 작업 공간이 **임시**라서 결과물은 꼭 GitHub 에 올린다.
- 막히는 곳은 대부분 **환경 설정**이다. 비밀값, 접속 허용 주소를 넣고 **새 세션**을 연다.
- 위험한 작업에서 멈추는 건 고장이 아니라 **안전장치**다.

클라우드 세션에서 집 서버 관리 프로그램을 연결한 실제 과정은 [Claude Code 클라우드 세션에 Proxmox 붙이기](https://autops.run/claude-code-proxmox-mcp/)에 정리해 두었다.
